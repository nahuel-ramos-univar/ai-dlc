# Sprint backlog proposal

Propose a backlog from approved work, current dependencies, and evidence of readiness. Do not invent team capacity, commitments, sprint identifiers, priorities, or dates; report them as unknown when evidence is missing and material.

For each candidate, state whether it already exists in Jira and is being **selected** into the backlog, or whether it still needs to be **created** and defined; do not blur that distinction. State the user outcome, prerequisite work, uncertainty, and why it may be ready. Surface sprint goal coherence, dependency order, missing prerequisite work, and blockers. Present alternatives where dependency order is uncertain, and report known team capacity only when the evidence for it is actually available.
